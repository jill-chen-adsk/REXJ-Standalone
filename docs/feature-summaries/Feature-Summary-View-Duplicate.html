Customer problem: building parallel view sets

Project teams build parallel view sets from one base set — for example, floor plans L1–L5 copied into Mechanical, Electrical, and Plumbing working views, each with its own View type, View template, and naming convention.

In Revit alone — per view, per discipline

  1. Duplicate the view (named "L2 Copy 1")
  2. Rename it to the office convention
  3. Change its view type
  4. Assign the discipline view template

5 levels × 3 disciplines = 15 new views, each needing a rename and a type/template check. Skipped templates, inconsistent prefixes, and leftover default names are easy to miss.

With View Duplicate — one dialog run

  1. Pick the source views once
  2. Add one rule per target set: text to add, view type, view template
  3. Click OK — every copy is created, named, typed, and templated

Consistent names across the set; name clashes are numbered instead of failing; any view that cannot be copied is listed.

View Duplicate

View Duplicate creates multiple copies of selected views in one step. Users pick source views, define one or more duplication rules, and the tool creates one new view per source view per rule — named with the rule's prefix or suffix, set to the rule's View type, and assigned the rule's View template. (Before: duplicate, rename, change type, and assign a template view by view. Now: one dialog run for the whole set.)

  • Filter by Discipline, View category, and View type, then multi-select in Views to duplicate (Shift / Ctrl)
  • Choose Duplicate or Duplicate with detailing
  • Add several rules to produce several view sets from the same sources in one run
  • Unique names automatically: an existing name gets a number appended, e.g. M-L2(1)
  • Views that cannot be duplicated are listed in one message; other copies are kept

View Duplicate

Main dialog

Narrow the list, then multi-select

Click View Copy on the Views panel. Choose Discipline and View category, and optionally a View type (or <All>). Select one or many views in Views to duplicate, then set Duplicate mode.

Templates and views Revit cannot duplicate are not listed. Last filters, mode, and dialog position are remembered.

View Duplicate

Duplication rules

One rule per output view set

The table shows Prefix / suffix, Added text, View template, and View type. Add creates a rule; Delete removes selected rows. Double-click Added text to edit in place.

Each selected view is copied once per rule: 4 views × 3 rules = 12 new views.

View Duplicate

Add rule

Set view type, template, and naming

Choose the target View type (same view family as the source views) and a View template for the same view category, or <None>. Pick Prefix or Suffix and enter Text to add — pre-filled with the template name.

If the view type assigns its own template on creation, View template shows it and is locked. Prefix/Suffix and the last view type are remembered.

View Duplicate

Run

Checked before, reported after

On OK, the tool checks for selected views, at least one rule, non-empty Added text, and matching view families. Problems are listed in one message before anything is created.

Each copy is created in its own step. If one fails, only that copy is undone; the rest are kept and the failed views are listed.

All copies are part of one Revit undo step.

Requested Feedback
  • How many duplication rules do you typically need in one run, and for which disciplines?
  • Should the dialog remember the full set of selected views between sessions?
  • Is the default naming for duplicates, e.g. M-L2(1), acceptable for your office standards?
  • Would you use Duplicate as Dependent if it were offered as a third mode?
  • Please let us know if you encounter any difficulties.
Development context

Weave dialogs, run reporting, and naming fixes are implemented and targeted for v1.1.7 (planned); final validation is in progress.

Known Limitations
  • Active document only; one Discipline and View category per run.
  • A rule's View type must match the source views' view family.
  • Duplicate as Dependent is not offered.
  • Only the first selected view is remembered between sessions.
  • Shift-range selection reported slow in some sessions; under investigation.
